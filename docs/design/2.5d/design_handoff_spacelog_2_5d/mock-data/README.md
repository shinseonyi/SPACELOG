# 예시 데이터 (온보딩 · 목업용)

시안(`design/spacelog-data.js`)이 쓰는 예시 데이터를 레포에 옮기기 쉬운 JSON으로 뽑았습니다.
처음 설치한 사용자가 빈 우주가 아니라 채워진 우주를 보고, 체험 가이드 12단계를 끝까지 따라갈 수 있게 하는 데이터입니다.

## 파일

| 파일 | 내용 | 개수 |
|---|---|---|
| `planets.json` | 행성 | 6 |
| `records.json` | 기록 (화면 문구의 "기록", 레포 타입의 `Star`) | 41 (텍스트 16 · 링크 12 · 파일 7 · CSV 6). 이미지 예시는 실제 이미지가 없어 뺐다 |
| `constellations.json` | 별자리 | 1 (체험 전용) |
| `onboarding-samples.json` | 체험 1단계에서 수집 앱 왼쪽에 놓이는 예시 카드 (이미지 카드는 뺐다) | 3 |

## 날짜는 상대값입니다

`records.json`의 날짜는 고정 날짜가 아니라 `daysAgo`(오늘부터 며칠 전) + `time`(그날의 시각, 로컬)입니다.
넣을 때 오늘 기준으로 바꿔야 합니다. 고정 날짜로 넣으면 며칠 뒤에는 아래 조건이 깨집니다.

- **오늘 넣은 기록이 있어야** 첫 화면(기간 "오늘")이 비지 않습니다. `daysAgo: 0`이 10개입니다 (CSV 6개 포함).
- **정확히 7일 전 기록이 있어야** 재발견 혜성 카드와 체험 10~12단계가 동작합니다. `s2`가 `daysAgo: 7`입니다.
- **7일이 넘은 기록이 있어야** 관측소 "재발견 혜성 관측"이 비지 않습니다. 8~13일 전 기록이 여러 개 있습니다.

```ts
const at = new Date(); at.setDate(at.getDate() - r.daysAgo);
const [h, m] = r.time.split(':').map(Number); at.setHours(h, m, 0, 0);
createdAtUtc = at.toISOString();
```

## 필드 대응 (제안)

레포의 실제 필드 이름에 맞춰 바꿔 주세요. 시안 쪽 이름은 레포를 읽지 않고 붙였습니다.

### planets.json
| 필드 | 뜻 | 레포 |
|---|---|---|
| `id`, `name` | | `Planet.id`, `Planet.name` |
| `color` | 색 이름 7가지 중 하나 (파랑 · 주황 · 보라 · 분홍 · 초록 · 빨강 · 하늘) | 새 필드. 지금의 `colorToken`(planet-1~8)을 대체 |
| `accent`, `base` | 그 색의 밝은 값·진한 값. 토큰으로 옮기면 생략 가능 | 토큰 |
| `shape` | `default` · `ring` · `nebula` | 새 필드 |
| `x`, `y` | 2.5D 우주 위 좌표. 행성 중심 사이 320 이상 | 새 필드 |

### records.json
| 필드 | 뜻 | 레포 |
|---|---|---|
| `id`, `planetId`, `title` | | `Star` |
| `kind` | `text` · `link` · `file` · `csv` (이미지 예시는 뺐다) | `csv`는 `file` + 표 데이터로 둬도 됩니다 |
| `source` | 목록 둘째 줄에 쓰던 값 (PNG · 1.8MB, 도메인 등) | 원본 경로·크기에서 계산 |
| `memo` | 사용자 메모 | `Star.memo` |
| `body` | 텍스트 기록의 본문. 목록에 앞 90자, 상세에 전체 | 새 필드 또는 원본 파일 내용 |
| `table` | CSV 기록의 `{ columns, rows }`. 관측소 대시보드가 씁니다 | 새 필드 (README 7장) |
| `preview` | 이미지 미리보기. 예시에는 실제 이미지가 없어 `null` | 아래 "알아 둘 것" |
| `daysAgo`, `time` | 넣은 때 (위 설명) | `createdAtUtc` |

### constellations.json
| 필드 | 뜻 |
|---|---|
| `name`, `purpose` | 별자리 이름, 관측 목적 |
| `recordIds` | `c6`(workouts.csv, CSV 데이터 행성) + `s14`(PRD 2차 의견, 제품 기획 행성) |
| `view` | 관측소 첫 보기 방식 |
| `onboardingOnly` | `true`: 처음부터 넣지 않습니다. 체험 6단계에서 만들고, 체험이 끝나면 지웁니다 |

## 언제 넣나

- **처음 실행할 때 한 번** (`Settings.onboardingDone`이 `false`인 사용자). 이미 기록이 있는 사용자에게는 넣지 않습니다.
- 예시 기록에는 표시를 남겨(`isSample: true` 등) 사용자가 "예시 기록 모두 지우기"를 할 수 있게 하는 것을 권합니다. 시안에는 이 기능이 없습니다.
- `web`의 목업 모드(`npm run dev:mock`)에서도 같은 데이터가 보이게 합니다. 시연용으로는 서버·`mocks/api`는 바꾸지 않고 `web/src/demo/`에서 넣습니다.

## 알아 둘 것

- **이미지 예시는 뺐습니다.** 실제 이미지 파일이 없어 빈 자리 표시로만 보였기 때문입니다. "사진 모아보기"를 시연하려면 이미지 파일과 함께 다시 넣어야 합니다.
- **파일 · 링크 예시는 이름뿐입니다.** "원본 열기"를 누르면 열 파일이나 주소가 없습니다. 링크는 실제 주소로 바꾸거나 예시라는 표시가 필요합니다.
- **CSV 6개는 사용자가 올려 준 파일**(`books`, `cafes`, `classes`, `movies`, `songs`, `workouts`)입니다. `classes.csv`의 상세링크 열은 `http://127.0.0.1:8000/...`이라 열리지 않습니다.
- **체험 1단계 예시 카드**(`onboarding-samples.json`) 중 실제로 넣어지는 것은 3번째(링크)입니다. 나머지는 사용자가 끌어다 놓을 수 있는 선택지입니다. 카드는 수집 앱의 데모용 틀(왼쪽 영역)에 있으므로, 실제 앱에서 온보딩을 어떻게 보여 줄지는 팀이 정해야 합니다.
